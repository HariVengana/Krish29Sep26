# LangChain Data Ingestion & Document Loaders

<h2 style="color: #2E86C1; border-bottom: 2px solid #2E86C1; padding-bottom: 5px;">1. The Role of Data Ingestion in RAG</h2>

In a Retrieval-Augmented Generation (RAG) architecture, **Data Ingestion** is the foundational step. Before an LLM can reason over private or external data, that data must be extracted from its source and loaded into memory. 

LangChain standardizes this process using **Document Loaders**. Regardless of the source (PDF, database, API, or webpage), loaders convert raw data into a standard LangChain `Document` object containing:
1.  **`page_content`**: The raw extracted text payload.
2.  **`metadata`**: A dictionary containing source origins (e.g., file path, URL, page number, author).

Text Files (TextLoader)
The simplest form of ingestion. It reads a .txt file and stores the entire string in a single Document.

Python
from langchain_community.document_loaders import TextLoader

loader = TextLoader("data/speech.txt")
docs = loader.load()

print(f"Content: {docs[0].page_content[:100]}...")
print(f"Metadata: {docs[0].metadata}") 
# Output: {'source': 'data/speech.txt'}

PDF Files (PyPDFLoader)
PDFs are paginated. PyPDFLoader is highly efficient because it automatically splits the PDF so that each page becomes its own separate Document object.

Python
from langchain_community.document_loaders import PyPDFLoader

loader = PyPDFLoader("data/attention_is_all_you_need.pdf")
docs = loader.load()

print(f"Total Pages: {len(docs)}")
print(f"Metadata of Page 1: {docs[0].metadata}") 
# Output: {'source': 'data/attention_is_all_you_need.pdf', 'page': 0}

AI Engineer Pro-Tip: For massive PDFs (e.g., 1000+ pages), use loader.lazy_load() instead of loader.load(). This yields an iterator rather than loading the entire list into RAM at once, preventing memory overflow.

Loading raw web pages using WebBaseLoader pulls in massive amounts of "noise" (navbars, footers, JavaScript tags). Passing this raw noise to an LLM wastes your limited Context Window and spikes API costs.

Solution: Combine WebBaseLoader with BeautifulSoup (bs4.SoupStrainer) to extract only the target HTML classes containing the actual article.

Python
from langchain_community.document_loaders import WebBaseLoader
import bs4

# 1. Define the targeted extraction (Token Optimization)
target_classes = bs4.SoupStrainer(
    class_=("post-title", "post-content", "post-header")
)

# 2. Initialize loader with kwargs to filter the HTML
loader = WebBaseLoader(
    web_paths=("[https://lilianweng.github.io/posts/2023-06-23-agent/](https://lilianweng.github.io/posts/2023-06-23-agent/)",),
    bs_kwargs={"parse_only": target_classes}
)

docs = loader.load()

# The resulting page_content is now clean, token-efficient text devoid of navbars!
print(docs[0].page_content[:200])

LangChain abstracts complex API requests into simple, one-line loaders.

Academic Papers (arXiv)
You can directly download and parse academic research papers using their arXiv ID.

Python
from langchain_community.document_loaders import ArxivLoader

# Initialize with the paper ID. 
# max_docs is crucial to prevent downloading too much if a broad search term is used.
loader = ArxivLoader(query="1706.03762", max_docs=2)
docs = loader.load()

print(docs[0].metadata['Title'])       # Output: Attention Is All You Need
print(docs[0].metadata['Authors'])     # Output: Ashish Vaswani, Noam Shazeer...

Wikipedia
Instead of scraping Wikipedia manually, use the dedicated API loader to search and retrieve articles by keyword.

Python
from langchain_community.document_loaders import WikipediaLoader

# Search Wikipedia and return the top 2 matching articles
loader = WikipediaLoader(query="Generative AI", max_docs=2)
docs = loader.load()

print(docs[0].metadata['title'])
print(docs[0].metadata['source']) # Returns the Wikipedia URL
